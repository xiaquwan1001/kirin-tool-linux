## 正文

**一句话定位**：Kirin Tool for Linux 是华为/海思麒麟设备工具在 Linux 上的独立移植（.NET 10 + Avalonia）。它能解包 UPDATE.APP、用 fastboot/adb 读设备、经临时 VCOM loader 刷 Full-OTA 或 flashing.xml；GUI、无头 CLI（`kirin-tool-cli`）和 MCP server 共用同一份命令实现，不是三套代码。

**v2.4.13 这次改的是"诚实"**，不是堆功能。这版是审计+修复批次：

- **MCP 写语义不再撒谎**：`flash_ota` / `flash_xml` 明确标成真实写入，`vcom_unlock` / `oeminfo` / `downgrade_enable` 永远只确认计划。描述由 `CliWriteKind` 自动生成，不会再和实现漂移。
- **红线分区 AI 不能自决**：`oeminfo`、`nvme`、`persist`、`modem_secure` 这类分区，MCP 直接拒绝 `allow-redline`（JSON-RPC `-32602`）；覆盖只能用 CLI 的 `--allow-redline`，由人来做决定。
- **OKAY 判定消除假成功**：GUI 的 fastboot 写入现在必须"退出码 0 **且**设备回 OKAY"才算成功。以前 exit 0 就显示"刷写完成"，设备其实可能拒了。
- **SN 重写与 FRP 清除要显式确认**：对话框列出新旧值，点错不会静默执行。
- **写入前自动备份**：把计划里的红线分区加 `ptable` dump 进时间戳目录，写 `manifest.json`（文件名/大小/SHA256/状态）；best effort，loader 不支持 dump 只警告不阻断，想严格可加 `--require-backup`。
- **电量 <50% 横幅只是警告**，按设计永不阻断写入——50% 是人自己守的规矩。
- **17 套免硬件测试**（新增 WriteGates / McpProtocol / OtaPlan / PreOpBackup），GitHub Actions 与 USTC GitLab CI 双跑。

**三段真实命令**（参数与仓库一致）：

```bash
kirin-tool-cli doctor
# fastboot/adb 路径与版本、设备枚举、loader 清单、只读能力探测

kirin-tool-cli flash-ota base.app --json
# 只打印计划，gate=plan-only，exit 4 —— 一个字节都不写

kirin-tool-cli flash-ota base.app --yes
# 真写全部非红线分区；要写红线再加 --allow-redline
```

MCP 配置（换行分隔 JSON-RPC 2.0 over stdio）：

```json
{
  "mcpServers": {
    "kirin-tool": {
      "command": "/path/to/kirin-tool-cli",
      "args": ["mcp"]
    }
  }
}
```

**安装四格式**：`.deb`（`sudo apt install ./kirin-tool-linux_2.4.13_amd64.deb`，含 GUI + CLI + udev 规则）、AppImage、tar.gz、单文件 CLI（同时就是 MCP server）。USB 没权限就加组重登：Debian/Ubuntu 用 `sudo usermod -aG plugdev,uucp "$USER"`，Arch/CachyOS 用 `adbusers`，再 `sudo udevadm control --reload-rules && sudo udevadm trigger`。

**真机验证边界**（重要）：只有华为 P40 Pro（ELS-AN00）走通过完整 `flash-ota`——46/46 分区写入、`fastboot reboot` 后约 22 秒起机。其他机型、其他麒麟 SoC 没有全量验证；Kirin 990 4G 明确不支持，别拿 5G 的 loader 硬顶；BD 包的 gzip SUPER 合并也没上过真机。下面的截图是本机 headless 渲染的 v2.4.13 真实界面（没连设备，所以设备字段显示界面原生的 "Not Read"），不是上游或旧版图。

**风险提示**：刷机、解包、改 SN/FRP 都可能清数据甚至让设备起不来。先备份、确认固件和型号匹配、看清输出里的 `gate` 字段（`plan-only` / `refused` / `confirmed` / `applied`）再用 `--yes`。工具是社区独立维护，与华为/海思无关。
