Fork build of Kirin Tool for Linux 2.4.15 (downstream of Redminote11tech/kirin-tool-linux).

This release merges the two logs that v2.4.14 still wrote side by side. One operation is now one
session: a directory holding one machine timeline, one optional human transcript and one verdict.

Log merge
- One operation = one session = one directory + one main log. New layout:
  `${KIRIN_LOG_DIR:-~/.local/state/kirin-tool}/sessions/<yyyyMMdd-HHMMSS>-<pid>-<op>/` with
  `session.jsonl` (0600), `vcom-trace.txt` (optional, 0600) and `summary.json` (0600); the session
  directory is 0700. See docs/log-merge.md.
- `OperationLogger` is the only writer. `OperationLogger.BeginSession(op, tool)` produces the
  sessionId; every later scope in the same process shares it, so a "VCOM upload -> replug ->
  fastboot oem unlock" episode is one file, ordered by one monotonic `seq`.
- `Services/VcomSessionLogger` became an adapter: it keeps its human transcript (the GUI still shows
  the path) and now writes every line into the same session.jsonl as a structured event, mapped to
  phase=step with `frame`/`ack`/`port`/`stage` payloads. VcomFlasher.cs and FirmwareUnlocker.cs were
  not touched at all (StableParity hashes unchanged).
- Timeline correlation fields: `sessionId`, `seq`, `scopeId`, `parentId`, `capabilityId` (registry
  row) and `approvalId` (the approval fingerprint, also present in approvals.jsonl). Approval
  decisions are on the same timeline: the default audit sink tees into the session.
- New read-only `logs` command on both CLI and MCP (no confirm, no approval): `logs list`,
  `logs show <session|latest>`, `logs path <session>`; all JSON. It also reads the pre-2.4.15 files
  (`<category>/*.jsonl`, `vcom-*.log`) and reports them as `legacy: true` with a synthesized
  sessionId, so nothing already on disk becomes unreadable.
- GUI: the progress dialog now shows the session directory next to the existing log path (new
  `ProgressDialog.ShowSessionDirectory`; ShowLogPath behaviour unchanged).
- The old `vcom/`, `fastboot/`, `flash/` directories stay readable; nothing writes there any more.

Field compatibility
- Nothing was removed: `ts/pid/op/phase/tool/argv/exitCode/durationMs/stdoutTail/stderrTail/ok/verdictSource/notes`
  keep their meaning. New fields are additive: `sessionId/seq/scopeId/parentId/capabilityId/approvalId/step`
  plus the nested `frame/ack/port/stage/approval` objects.

Testing
- tests/OpLogging extended to 115 checks (session layout, seq monotonicity, summary.json on the
  failure path, capability/approval context, permissions); new tests/LogMerge (79 checks) proves the
  merge end to end with a shell stub named `fastboot`, no device involved: VCOM adapter + child
  process in one session.jsonl, legacy files still readable through `logs show`, `logs list --json`
  field completeness, summary.json on failure, 600/700 permissions, MCP `logs` read-only without
  confirm.
- 23 hardware-free suites run by both CI pipelines from tests/suites.txt, all green locally.
  StableParity: VcomFlasher.cs and FirmwareUnlocker.cs hashes unchanged; the two changed files
  (MainWindow.axaml.cs, UI/ProgressDialog.axaml.cs) only gained log-output lines, and the boundary
  hash was refreshed with that reason recorded in tests/StableParity/boundary.json.

Known gaps
- No GUI log browser yet: `logs` is CLI/MCP only.
- Sessions are per process: the MCP server process and the GUI process each write their own session
  (correlate them by timestamp/sessionId, not by file).
- Old log files are never pruned automatically.
