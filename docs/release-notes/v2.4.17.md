Fork build of Kirin Tool for Linux 2.4.17 (downstream of Redminote11tech/kirin-tool-linux).

One-line: the CI is quiet again — the ~50 warnings that were real defects or one-line hygiene are
gone (local `dotnet build`: 135 → 83 total warnings, of which 3 are Avalonia XAML AVLN3001 that CI
never reported), every platform deprecation notice is gone, and the cleared codes may not come back.

What was actually there
- The Actions summary showed ~19 warnings. The log of run 43443391616 contained 279
  `##[warning]` annotations, i.e. **130 unique sites** (119 app / 11 tests): GitHub caps how many
  annotations it renders, and the app project is compiled twice (directly and as a project reference
  of `KirinTool.Cli`), which duplicates every line.
- None of it was new breakage: `<Nullable>enable</Nullable>` was turned on after most of the code
  existed, so the compiler started reporting long-standing assumptions in bulk (CS8618/CS8625/CS8622
  and friends). Nothing gates a build.

Batch A (this release) — real defects and one-line hygiene
- `CS4014`: four `Dispatcher.UIThread.InvokeAsync(...)` calls in the dump/flash
  progress paths were fire-and-forget without saying so. Now `_ = `, same behaviour, intent explicit.
- `CA2022`: the VCOM BootROM drain used the inexact `Stream.ReadAsync(byte[],int,int,ct)` overload
  (`Services/VcomFlasher.cs`). The bytes are discarded, so this was not a data bug, but the read is now
  the `Memory<byte>` overload — no wire command, byte, timing or retry changed.
- `CS0168`: unused `ex` in a best-effort `File.Delete` catch (the audit already removed the others).
- `CS0618`: `OpenFolderDialog` → `StorageProvider.OpenFolderPickerAsync` (dump-partition target
  picker), `ToggleButton.Checked/Unchecked` → `IsCheckedChanged` (live-pull toggle),
  `IClipboard.GetTextAsync` → `ClipboardExtensions.TryGetTextAsync` (`tests/UdevNotice`).
- `CA1416`: three test harnesses called `File.SetUnixFileMode` without a platform guard; they now use
  the `if (!OperatingSystem.IsWindows())` form that `tests/LogMerge` already had.
- The `PropertyChanged` family (`CS0108`/`CS8612`/`CS8618`/`CS8622`, ~29 sites): one copy-pasted
  `INotifyPropertyChanged` block, declared non-nullable, in five POCO models and four
  `AvaloniaObject` subclasses. The models get a nullable event; the four UI classes get
  `public new event PropertyChangedEventHandler? PropertyChanged` — `new` because
  `AvaloniaObject` already declares `PropertyChanged`, and this keeps runtime behaviour identical.
  Dropping the hand-written INPC in favour of `RaisePropertyChanged` is tracked separately (batch B+),
  not smuggled into a warning cleanup.

CI hygiene (same commit series)
- Actions bumped to `node24` majors: `checkout@v7`, `setup-dotnet@v6`, `upload-artifact@v7`,
  `download-artifact@v8` — clears the Node.js 20 deprecation warning at the source, instead of waiting
  for the 2026 forced migration.
- Every job pins an explicit runner image. `ubuntu-latest` → `ubuntu-24.04`; the deb gate runs a
  pinned `ubuntu-24.04` + `ubuntu-26.04` matrix. A silent `latest` migration would otherwise change
  what the "Depends are satisfiable" gate proves without any commit saying so.
- The release container stays `ubuntu:20.04` on purpose: it is a build sandbox for the glibc 2.31
  floor, and moving it to 24.04 would raise that floor to 2.39 — a product support decision, recorded
  in [portable-appimage.md](portable-appimage.md).
- `Kirin-Tool.csproj`: `<WarningsAsErrors>CS4014;CS0168;CA2022;CA1416</WarningsAsErrors>` — the codes
  this release cleared may not come back. Nullable codes are deliberately not gated yet.

Still open (batch B, next)
- ~80 nullable-reference warnings remain (CS8618/CS8625/CS8600/CS8602/CS8603/CS8604/CS8620), almost all on signatures: `string op = null`,
  `IProgress<string> progress = null`, non-nullable fields set outside the constructor, and a handful
  of `CS8600/CS8602/CS8603/CS8604`. They touch `FastbootClient`, `ProcessRunner`, `VcomFlasher`,
  `UsbDownloadService` and `FirmwareUnlocker` — the flashing hot paths — so they get their own commit
  and a full `tests/suites.txt` run. Policy and batch definitions:
  [warnings-policy.md](warnings-policy.md).

Verification
- `dotnet build Kirin-Tool.csproj -c Release --no-incremental`: 135 → 83 warnings, 0 errors
  (CS0108/`CS8612`/`CS8622`/`CS4014`/`CS0168`/`CS0618`/CA1416/CA2022 all at zero).
- `tests/suites.txt`: all 25 hardware-free harnesses pass (1431 PASS lines), including
  `StableParity` after the boundary hashes were refreshed with the "behaviour unchanged" note.
- No device command, wire byte, timing or retry was touched by this release; there is nothing new to
  verify on hardware.
